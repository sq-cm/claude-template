# Report template

Write the aggregated report to `Vault/Plans/claudemd-review-YYYY-MM-DD.md` (create
`Vault/Plans/` if absent; append `-2`, `-3`… if the name is taken). Structure:

---

# CLAUDE.md Review — [DD/MM/YYYY]

> **Maintainer review required — this report changes nothing by itself.**
> Generated by `/review-claudemd`. Report-only: no CLAUDE.md file was modified.

## Window analysed

- Sessions: [N] (most recent, ≥ [min-size] bytes, current session excluded[, since DD/MM/YYYY])
- Fork/resume duplicates dropped at extraction: [N, from the manifest's `droppedForkDuplicates` — forks copy whole histories, so without this the same conversation would count as evidence more than once]
- Sparse sessions skipped: [N, from `skippedSparse` — passed the raw size floor but extracted to < 500 chars of signal]
- Span: [oldest session date] – [newest session date]
- Extraction: [total raw MB] → [total extracted KB] across [N] files
- Analysts dispatched: [N] batches
- CLAUDE.md tiers reviewed: global (`~/.claude/CLAUDE.md`), root, [folder-tier list or "no folder-tier files found"]

## 1. Violated — rules that didn't fire

For each finding:

### V1. [short title]
- **Rule:** `<file>` § [section] — "[rule text]"
- **Evidence:** [session-id(s)] — "[excerpt]"
- **Suggested change:** [rewording / reinforcement, concrete replacement text where possible]
- **Confidence:** high | medium | low ([corroborated by N batches / single batch])

## 2. Missing — local (root or folder-tier CLAUDE.md candidates)

[Same finding shape; `Pattern:` instead of `Rule:`. Name the target file and section.]

## 3. Missing — global (`~/.claude/CLAUDE.md` candidates)

[Same shape. Note: the global file is personal — the template never ships these; this
section is advice to the human only.]

## 4. Outdated — dead weight or demotion candidates

[Same shape. Distinguish "never exercised in window" (weak, needs a longer window)
from "references something that no longer exists" (strong). Name the destination SOP
when recommending demotion.]

## 5. Friction — followed but disproportionate

[Same shape. Each suggestion is a simplification, never a deletion.]

## Discarded findings

One line each: findings reported by an analyst but dropped at aggregation, with the
reason (duplicate, no evidence, misread rule, hook noise mistaken for behaviour).
Keeps the aggregation auditable.

---

Aggregation rules:

- Dedupe on (lens, implicated file+section) — for the MISSING lenses that key is the
  analyst's required `target:` field. Merge evidence lists, keep the strongest
  suggestion, bump confidence when ≥ 2 batches independently report it.
- OUTDATED claims are only medium+ confidence when NO batch shows the rule firing.
- Order findings within each lens by confidence, then by blast radius of the suggested change.
- Australian English throughout.
