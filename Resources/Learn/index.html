AI Team — Onboarding Guide

Everything you need to start working with your AI team — or to set up a new vault for a client.

Last synced:  ·  Source of truth: CLAUDE.md

Why use this?

This isn't a content generator you point at a blank page. It's a small studio of specialists (Sam the Orchestrator at the front desk, 28 named personas behind them) that routes your request to whoever owns that kind of work, checks it before it ships, and remembers what it learned last time.

Who this is for

The six profiles below aren't roles you have to pick — they're six reasons people end up using this vault. Find the one closest to you, then read the round table at the end, where they push back on each other. Nothing here is a guarantee; it's a description of a trade.

Solo founder / consultant

Who this is: one person doing the work of a marketing department, with no budget to hire one.

A whole studio, without hiring anyone.

You get specialists in copy, SEO, brand strategy, visual production and analytics — you're still the only person in the room, but the room got bigger.

Best way to use it: run everyday jobs through the Fast-Path Lane (single-file, reversible work skips the full pipeline). For anything bigger, let Sam route you to @{Copywriter}, @{BrandStrategist}, and so on.

The catch: one session, one Orchestrator — not 28 people working in parallel. You still queue the work; you just don't do every part of it yourself.

Small agency owner

Who this is: running client work through a small team, where a mistake in a deliverable is a client-facing problem, not an internal one.

Nothing reaches a client unchecked.

Every file heading to 03 Deliverables/ goes through the QA Compliance Reviewer first, with an Advisor Checkpoint before drafting and before handoff on durable work.

Best way to use it: treat the QA Gate (PASS / FLAGGED / BLOCKED) as non-negotiable. Route regulated-category copy through @{LegalComplianceWriter} before it goes near a client.

The catch: Advisor Checkpoints and the QA Gate run on Fable 5 (claude-fable-5) — real token cost on every checkpoint-eligible job. Client safety isn't free.

In-house marketing lead

Who this is: owns the brand and content function inside a company, working with the same voice and positioning across many pieces of work over time.

Skip the re-briefing, keep the depth.

Talk to the exact specialist you need — @{Copywriter}, @{SEOSpecialist}, @{BrandStrategist} — and your messaging architecture persists as a source-of-truth document, not a one-off output.

Best way to use it: address specialists directly with @{RoleToken} when you know what you need. Keep strategy documents (from @{BrandStrategist} and @{ContentStrategist}) as living references other requests can cite.

The catch: direct addressing still goes through Sam's routing and, where eligible, the same grill-me/plan/checkpoint pipeline as anyone else.

Freelance creative

Who this is: handles the actual creative production — video, stills, motion — for clients who expect a polished, presentable outcome, not a raw file.

A real production stack, not one generalist.

Cinema Showrunner, Stills Director, Seedance Director, Visual AI Producer and Video & Motion Producer each cover a different part of the work, and the HTML Deliverable Companion turns a finished report into something a client can click through.

Best way to use it: brief the right director for the medium — @{CinemaShowrunner} for narrative/video structure, @{StillsDirector} or @{SeedanceDirector} for image and short-form motion. Offer the HTML companion once the Markdown version has passed QA.

The catch: some of this depends on plugin-provided capability — a generation or visual tool only works if that plugin is installed. Check before you brief around it.

Ops / automation person

Who this is: less interested in any single piece of output, more interested in making the system itself reliable and repeatable.

You get to build the machine, not just use it.

Access to the persona architecture, the slash commands, the memory layer, and the two people whose job is building and maintaining that machinery.

Best way to use it: work with @{AutomationArchitect} and @{CreativeTechnologist} on anything structural. Use /update to pull template improvements and /memory-reconcile to fold session notes into context.md; consult Resources/Git/INDEX.md before checkpoint-eligible work.

The catch: sub-agents are depth-1 — only the Orchestrator can dispatch them, and every persona routes back through Sam rather than talking to each other directly. Hub-and-spoke, not a mesh.

Non-technical team member

Who this is: needs to get something done in here without knowing, or wanting to know, how any of it works underneath.

You don't need to know who does what.

Sam figures out routing for you; grill-me asks one question at a time instead of demanding a perfect brief, and plan mode shows the approach before anything happens.

Best way to use it: describe what you want in plain language and let Sam route it. If you're not sure your request is clear, run /prompt-review first — it coaches the ask before you send it.

The catch: this is a Claude Code template, not a polished SaaS product — there's a genuine learning curve to the conventions (folders, checkpoints, what goes where), even with the guardrails softening it.

What is this?

You have access to a team of 28 AI specialists — a copywriter, SEO strategist, UX designer, brand strategist, and more. A coordinator called Sam (the Orchestrator) receives everything you send and routes it to the right person. You don't manage the routing — you just describe what you need.

Using Claude Code: Claude Code is a chat interface that runs in your terminal or IDE. Type your message and press Enter — that's it. Everything in this guide assumes you have Claude Code open with this workspace as your working directory.

How a request flows

Here's what happens when you send a real request — from your message to a finished deliverable.

You

Sam — routing

Before drafting, checking the repo library for content strategy frameworks. Running Checkpoint A with Odin (Senior Adviser) before committing to a structure…

Here's the content architecture: three pillar topics — Origin Stories, Brewing Methods, and Ethical Sourcing. Supporting cluster topics mapped to search intent. Brief prepared for Finn.
Finn — Copywriter
Working from Sage's brief. Running Checkpoint B before delivery…

First article drafted: "Why Single-Origin Coffee Tastes Different (And Why It Matters)." 800 words, conversational but informed. Ready for Quinn's pass.
Quinn — QA Reviewer

Sam — handoff complete
Article delivered to Projects/[Client]/03 Deliverables/. Quinn flagged one citation — Finn will add it. Let me know when you're ready for article two.

How to talk to the team

Three ways to address the team. Pick the one that matches how much you already know.

Open request

"I need a first draft of a client welcome email for a new skincare brand."

No @ needed. Sam reads your request and routes it to the best-fit specialist.

Direct address

"@{Copywriter} write a 200-word homepage intro for Meridian Law. Tone: authoritative but approachable."

Use @{RoleToken} when you know who you need. Bypasses Sam's routing step.

Both @{Copywriter} and @Finn work — use whichever feels natural.

Multi-step request

"I need a full social calendar for NovaStar Gym — strategy, post copy, and visual direction for Instagram."

Sam will loop in Sage, Juno, and Cleo in sequence. You'll see the handoffs happen.

Declared plugins auto-install on first launch after the one-time trust prompt — you generally don't need to run anything here. If one failed to auto-install, .claude/commands/onboard.md Steps 3.5 and 3.55 give the exact /plugin marketplace add + /plugin install pair for each. Example (superpowers, shipped as superpowers@claude-plugins-official):

Keeping your vault updated

When the template repo receives updates, run /update from your vault root. It pulls them in using the two-branch model without overwriting your personal work.

1

Run the update command

/update

Fetches latest from origin, fast-forwards main as a clean upstream mirror, then rebases your personal local/main branch on top. Guards against missing local/main (run /onboard first) and uncommitted changes.

Equivalent raw git command if you prefer manual execution:

git fetch origin && git checkout main && git merge --ff-only origin/main && git checkout local/main && git rebase main
2

If rebase hits a conflict

Git pauses and shows which file conflicted. Resolve it, then:

git add [file] && git rebase --continue

To abort and return to your previous state: git rebase --abort

Your personal files (Projects/, Vault/Memory/, Inbox/) are never affected — conflicts only appear when both you and the template edited the same core file.
